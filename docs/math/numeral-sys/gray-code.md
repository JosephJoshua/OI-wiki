Gray code is a binary numeral system in which any two adjacent numbers differ in exactly one bit. For example, the Gray code sequence for $3$-bit numbers is

$$
000,001,011,010,110,111,101,100
$$

Note that the sequence is indexed from $0$, so $G(0)=000,G(4)=110$.

Gray code was introduced by Frank Gray of Bell Labs in the 1940s and was patented in 1953.

## Constructing Gray code (the transform)

There are many ways to construct Gray code. We first describe how to build it by hand, then give code for it along with a proof of correctness.

### By hand

The $k$-bit Gray code can be built as follows. Start from the all-$0$ code and use these rules:

1.  Flip the lowest bit to get the next code (for example $000\to 001$);
2.  Flip the bit to the left of the rightmost $1$ to get the next code (for example $001\to 011$);

Apply these rules alternately $2^{k-1}$ times to get the $k$-bit Gray code sequence.

### Reflection

The $k$-bit Gray code can be obtained quickly from the $(k-1)$-bit Gray code: reflect the list top to bottom and add a new bit in front, as shown below:

$$
\begin{matrix}
k=1\\
0\\ 1\\\\\\\\\\\\\\
\end{matrix}
\to \begin{matrix}\\
\color{Red}0\\\color{Red}1\\\color{Blue}1\\\color{Blue}0\\\\\\\\\\
\end{matrix}
\to \begin{matrix}
k=2\\
{\color{Red}0}0\\{\color{Red}0}1\\{\color{Blue}1}1\\{\color{Blue}1}0\\\\\\\\\\
\end{matrix}
\to \begin{matrix}\\
\color{Red}00\\\color{Red}01\\\color{Red}11\\\color{Red}10\\\color{Blue}10\\\color{Blue}11\\\color{Blue}01\\\color{Blue}00
\end{matrix}
\to \begin{matrix}
k=3\\
{\color{Red}0}00\\{\color{Red}0}01\\{\color{Red}0}11\\{\color{Red}0}10\\{\color{Blue}1}10\\{\color{Blue}1}11\\{\color{Blue}1}01\\{\color{Blue}1}00
\end{matrix}
$$

### Formula

Let us compare the binary form of $n$ with $G(n)$. Bit $i$ of $G(n)$ is $1$ exactly when bit $i$ of $n$ is $1$ and bit $i+1$ is $0$, or bit $i$ is $0$ and bit $i+1$ is $1$. So we can compute it with an XOR:

$$
G(n)=n\oplus \left\lfloor\frac{n}{2}\right\rfloor
$$

```cpp
int g(int n) { return n ^ (n >> 1); }
```

### Proof of correctness

Next we prove that in the Gray code sequence generated by this formula, any two adjacent codes differ in exactly one bit.

Consider the difference between $n$ and $n+1$. Adding $1$ to $n$ flips the run of trailing $1$s in its binary form and then turns the lowest $0$ into $1$. We write the bits of $n$ and $n+1$ like this:

$$
\begin{aligned}
(n)_2 &= \cdots0\underbrace{11\cdots11}_{k\text{ bits}}\\
(n+1)_2 &= \cdots1\underbrace{00\cdots00}_{k\text{ bits}}
\end{aligned}
$$

So when computing $g(n)$ and $g(n+1)$, the last $k$ bits both become $\displaystyle\underbrace{100\cdots00}_{k\text{ bits}}$, while bit $k+1$ differs. This is because $n$ and $n+1$ agree on every bit except the last $k+1$, so bit $k+1$ is either XORed with $1$ in both cases or XORed with $0$ in both cases. Either way, bit $k+1$ ends up different. All bits other than the last $k+1$ go through the same XOR, so they end up the same.

This completes the proof.

## Recovering the number from its Gray code (the inverse transform)

Now consider the inverse transform: given a Gray code $g$, find the original number $n$. We go through the bits from the highest to the lowest (the lowest bit, the ones bit, has index $1$; the highest has index $k$). Bit $i$ of $n$ is related to bit $g_i$ of $g$ as follows:

$$
\begin{aligned}
n_k &= g_k \\
n_{k-1} &= g_{k-1} \oplus n_k &&= g_k \oplus g_{k-1} \\
n_{k-2} &= g_{k-2} \oplus n_{k-1} &&= g_k \oplus g_{k-1} \oplus g_{k-2} \\
n_{k-3} &= g_{k-3} \oplus n_{k-2} &&= g_k \oplus g_{k-1} \oplus g_{k-2} \oplus g_{k-3} \\
&\vdots\\
n_{k-i} &=\displaystyle\bigoplus_{j=0}^ig_{k-j}
\end{aligned}
$$

```cpp
int rev_g(int g) {
  int n = 0;
  for (; g; g >>= 1) n ^= g;
  return n;
}
```

## Applications

Gray code has some very useful applications, and some of them are quite surprising:

-   The Gray code sequence of $k$-bit numbers forms a Hamiltonian cycle through the vertices of a hypercube in $k$-dimensional space (a square in two dimensions, a unit segment in one dimension). Each bit of the Gray code is the coordinate in one dimension.

-   Gray code is used to minimize errors in signal transmission in digital-analog converters (such as sensors), because only one bit changes at a time.

-   Gray code can be used to solve the Tower of Hanoi puzzle.

    Let the number of disks be $n$. Start from the all-$0$ $n$-bit Gray code $G(0)$ and move to the next code each time ($G(i)$ to $G(i+1)$). Bit $i$ of the current Gray code stands for the $i$-th disk, counting from smallest to largest.

    Since only one bit changes at each step, when bit $i$ changes, we move disk $i$. During the moves, every disk except the smallest has only one possible place to go. When moving the smallest disk, we always have two choices. So the strategy is:

    If $n$ is odd, the smallest disk moves along the path $f\to t\to r\to f\to t\to r\to\cdots$, where $f$ is the starting peg, $t$ is the peg where we want all the disks to end up, and $r$ is the remaining peg.

    If $n$ is even: $f \to r \to t \to f \to r \to t \to \cdots$

-   Gray code is also used in the theory of genetic algorithms.
