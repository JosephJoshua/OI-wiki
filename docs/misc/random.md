## Overview

To use randomization techniques, we first need to be able to generate random numbers quickly. This article introduces common ways to generate random numbers.

### Random numbers and pseudo-random numbers

It is meaningless to call a single number "random", so below we always talk about "random sequences". Even when we say "a random number", we mean "an element of a random sequence".

Today's computers compute deterministically. So it is impossible to generate a truly **unpredictable** and **non-repeatable** random sequence using an algorithm alone.

However, in most cases we do not need such strong randomness. We only need the generated sequence to statistically have the features of a random sequence (such as uniform distribution, independence, and so on). Such a sequence is called a **pseudo-random number** sequence.

Some examples of random and pseudo-random numbers in real life and in algorithms:

-   Sampling surveys usually only need pseudo-random numbers, because we only care about statistical features in the first place.
-   Network security often needs stronger random numbers (than the pseudo-random numbers just mentioned), because attackers may exploit predictability.
-   Randomized algorithms used in OI/ICPC almost always only need pseudo-random numbers. These algorithms usually introduce random numbers to bring probability into the complexity analysis and thereby lower the complexity. In essence, this still only uses the statistical features of random numbers.
-   Some randomized algorithms (such as [Moser's algorithm](https://en.wikipedia.org/wiki/Algorithmic_Lov%C3%A1sz_local_lemma)) use entropy-related properties of random numbers, so they must use truly random numbers.

## Ways to generate random numbers

### `rand`

Generates pseudo-random numbers. Its drawback is that it is fairly slow. You need `#include<cstdlib>` to use it.

Calling `rand()` returns a random non-negative integer in `[0,RAND_MAX]`, where `RAND_MAX` is a macro in the standard library. On Linux, `RAND_MAX` equals $2^{31}-1$. You can use the modulo operation to limit the size of the generated numbers.

`rand()` needs a random seed. You can use `srand(seed)` to change the seed to `seed`. Of course, you can also skip initializing it.

If the same program runs twice with the same `seed`, on the same machine and with the same compiler, the random results will be the same.

One option is to use the current system time as the seed: `srand(time(nullptr))`.

??? warning "Warning"
    On `Windows`, `rand()` returns values in $\left[0,2^{15}\right)$ (that is, `RAND_MAX` equals $2^{15}-1$). When you need numbers of at least $2^{15}$, it is recommended to use `(rand() << 15 | rand())` to generate larger random numbers.

On the randomness of `rand()` and `rand()%n`:

-   The C/C++ standards make no requirements at all about the quality of the random numbers generated by `rand()`.
-   GCC's implementation of `rand()` guarantees basic properties such as uniform distribution, but it has obvious flaws such as short periods in the low bits. (For example, on the author's machine, the sequence produced by `rand()%2` has a period of about $2\cdot 10^6$.)
-   Even if we assume `rand()` is uniformly random, `rand()%n` is not guaranteed to be uniform, because the numbers in `[0,n)` may appear different numbers of times among `0%n,1%n,...,RAND_MAX%n`. For a method that strictly guarantees uniformity, see [Daniel Lemire, Fast Random Integer Generation in an Interval](https://arxiv.org/abs/1805.10941).

### Predefined random number generators

Several popular algorithms are defined. Unless stated otherwise, they are all defined in the header `<random>`.

??? warning "Warning"
    Predefined random number generators are available starting from the C++11 standard[^ref2].

#### Mersenne Twister

The Mersenne Twister was proposed by Matsumoto and Nishimura in 1998[^ref3]. It is named after the fact that one of its implementations, MT19937, has a period as long as the Mersenne prime $M_{19937} = 2^{19937} - 1$.

Since C++11, the class template `std::mersenne_twister_engine` implements a random number generator based on this method. Because it is very complicated to use directly, in practice we usually use its specializations: `std::mt19937` and `std::mt19937_64`. Their advantages are high-quality random numbers and much faster speed than `rand()`.

`mt19937` is based on the 32-bit Mersenne Twister proposed by Matsumoto and Nishimura in 1998[^ref3]. It is a random number generator class that works like `rand()`, and its range is the range of `unsigned int`. To use it, define a generator with it: `mt19937 myrand(seed)`. `seed` is optional; if omitted, the default seed is used. It overloads `operator()`, so whenever you need a random number, just call `myrand()`.

A similar generator is `mt19937_64`, based on the 64-bit Mersenne Twister proposed by Matsumoto and Nishimura in 2000. It is used the same way as `mt19937`, but its range extends to the range of `unsigned long long`.

#### Linear congruential generator

The linear congruential generator (LCG) was proposed by Thomson and Rotenberg in 1958. Its formula is as follows, where $A, C, M$ are predefined constants:

$$
s_i \equiv \begin{cases}
\operatorname{seed} & i = 0 \\
s_{i-1} \times A + C & i \ge 1
\end{cases}\pmod{M}
$$

Since C++11, the class template `std::linear_congruential_engine` implements a random number generator based on this method. Its template parameters are:

```cpp
template <class UIntType, UIntType A, UIntType C, UIntType M>
class linear_congruential_engine;
```

Here `UIntType` is the type of $s$, followed by the three constants.

Later, in 1969, Lewis, Goodman, and Miller showed that with $A = 7^{5} = 16807$, $C = 0$, $M = 2^{31} - 1 = 2147483647$, this algorithm reaches almost the maximum period for this modulus, $2^{31} - 2$ (because $16807$ is a [primitive root](../math/number-theory/primitive-root.md) modulo this number), and has fairly good statistical properties.

Then in 1988, Park and Miller adopted the LCG with these parameters as the "minimal standard", simply because it is extremely simple, easy to understand, efficient, and of reasonable quality. Finally, in 1993, Park, Miller, and Stockmeyer changed $A$ to $48271$, which became the newer "minimal standard". Both versions of the "minimal standard" are predefined in C++11 as specializations of `linear_congruential_engine`: `minstd_rand0` and `minstd_rand`. Specifically:

-   For `minstd_rand0`, $s_i$ has type `std::uint_fast32_t`, $A$ is $16807$, $C$ is $0$, and $M$ is $2147483647$.

-   For `minstd_rand`, $s_i$ has type `std::uint_fast32_t`, $A$ is $48271$, $C$ is $0$, and $M$ is $2147483647$.

Using them is simple. First define `std::minstd_rand myrand(seed);`, where `seed` is the seed (default $1$ if omitted). Then call `myrand()` to get a random number.

If you need a custom generator of this form where $A, C, M$ are not constants, you can also write one by hand. This is easy to implement, but the period of the generated sequence is fairly short (at most $M$, and in most cases shorter than $M$).

### Non-deterministic uniformly distributed integer random number generator

`random_device` is a hardware-based uniformly distributed random number generator. It can generate random numbers quickly **until the entropy pool is exhausted**. This class is defined in C++11 and needs the `random` header. Since its performance drops sharply once the entropy pool is exhausted, it is recommended to use it to generate seeds for pseudo-random generators such as `mt19937`, rather than to generate the random numbers directly.

`random_device` is a non-deterministic uniform random bit generator, although an implementation is allowed to use a pseudo-random engine if non-deterministic generation is not supported. So far the author has not received any report that NOIP judging machines do not support hardware-based uniform random number generation. ### Other methods

Sometimes we need to write our own random number generator. Here are some commonly used methods.

#### Xorshift

Usage is similar to most of the generators above: first define a generator `xorshift32 rng32(seed)` or `xorshift64 rng64(seed)`, where `seed` is the seed (the default seed is used if omitted); then call `rng32()` or `rng64()` to get random numbers. When the seed is not $0$, these two generators have periods $2^{32} - 1$ and $2^{64} - 1$ respectively. Because they are so simple to implement, problem setters often give contestants the generator and a seed to produce large input data, reducing I/O overhead.

#### Lagged Fibonacci generator

Generate the random sequence $\{R_i\}$ with the following formula (where $0 < j < k$):

$$
R_i \equiv R_{i-j} \star R_{i-k} \bmod P
$$

Here $P$ is usually a power of $2$ (commonly $2^{32}$ or $2^{64}$), and $\star$ is a binary operator, which can be addition, subtraction, multiplication, or XOR.

Compared with the traditional linear congruential generator, this method has a longer period, but its randomness depends heavily on the initial conditions.

## Randomized algorithms

Below are some randomized algorithms defined in the C++ standard that rely on random number generation.

### `random_shuffle`

`std::random_shuffle` was introduced in C++98 and randomly shuffles a given sequence. You need `#include<algorithm>` to use it. It is usually implemented with the [Fisher-Yates algorithm](https://en.wikipedia.org/wiki/Fisher%E2%80%93Yates_shuffle).

To use it, pass pointers or iterators to the start and end of the range (half-open): `std::random_shuffle(first, last)` or `std::random_shuffle(first, last, myrand)`.

By default it uses `rand()` internally as the random number generator. Of course, you can also pass a custom generator.

On the randomness of `random_shuffle`:

-   The C++ standard requires `random_shuffle` to choose among all possible permutations **with equal probability**, but libstdc++, the default standard library of GCC[^note1], does **not** strictly follow this.
-   One reason for the randomness flaws of `random_shuffle` in GCC is that it uses something like `rand()%n`. As mentioned earlier, this does not produce uniformly random integers.
-   The second reason is that the range of `rand()` is limited. If the length of the range passed in exceeds `RAND_MAX`, some permutations **can never** be produced[^ref1].

??? warning "Warning"
    `random_shuffle` was deprecated in the C++14 standard and removed in the C++17 standard.

### `shuffle`

`std::shuffle` was introduced in C++11 and does the same job as `random_shuffle`. You need `#include<algorithm>` to use it.

The difference is that you must pass a custom random number generator: `std::shuffle(first, last, myrand)`.

GCC's[^note1] implementation of `shuffle` meets the C++ standard's requirement, that is, it chooses among all possible permutations with equal probability.

### `sample`

`std::sample` was introduced in C++17 and randomly picks $n$ elements from a sequence. The main difference from taking the first $n$ elements after a `shuffle` is that the chosen elements keep their relative order in the output. It is usually implemented with [reservoir sampling](https://en.wikipedia.org/wiki/Reservoir_sampling).

Usage: `std::sample(first, last, dest, n, myrand)`, where `[first, last)` is the range to sample from, `[dest, dest + n)` is where the output goes, and `myrand` is the random number generator to use.
